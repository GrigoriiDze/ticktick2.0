# TickTick 2.0 — Руководство разработчика

Кроссплатформенный менеджер задач, привычек и времени (Web, Android, Windows Desktop).

---

## 1. Стек технологий

- **Фронтенд:** React 19, TypeScript, Vite 7.
- **Стилизация:** Чистый CSS с CSS-переменными и дизайн-токенами (`src/tokens.css`, `src/styles.css`).
- **Мобильная платформа (Android):** Capacitor 8 (нативные плагины: пуши, микрофон, статус-бар, файловая система, шеринг).
- **Десктоп (Windows):** Tauri v2 (Rust + WebView2).
- **Бэкенд и Синхронизация:** Firebase Firestore (с офлайн-кэшем `persistentLocalCache`), Firebase Authentication, Firebase Hosting.
- **Тесты:** Vitest (350+ тестов на чистую логику домена и утилит).

---

## 2. Быстрый старт

### Требования
1. **Node.js:** версия 20+ (рекомендуется 20.x или 22.x).
2. **Для сборки Android:** JDK 17 или 21, Android SDK (Android Studio).
3. **Для сборки Windows Desktop:** Rust + Cargo (`rustup toolchain install stable-msvc`).
4. **Firebase CLI:** `npm i -g firebase-tools` (для деплоя хостинга и правил).

### Установка зависимостей
Вся кодовая база фронтенда находится в папке `app/`:
```bash
cd app
npm install
```

### Режим разработки (Web)
```bash
cd app
npm run dev
```
Сервер запустится по адресу: `http://localhost:5173/`.

### Запуск тестов
```bash
cd app
npm run test
```
Тесты проверяют логику повторов, фильтров, дат, смарт-парсинга, сортировки, импорта и локального хранилища.

## 4. Сборка и выпуск релизов

### 1. Веб-версия (Firebase Hosting)
Сборка фронтенда и копирование в папку `hosting/`:
```bash
cd app
npm run web
```
Публикация на хостинг (из корня проекта):
```bash
firebase deploy --only hosting
```
Сайт доступен по адресу: **https://ticktick-47613.web.app**

---

### 2. Сборка Android APK
В проекте настроен полностью автоматический релиз:
1. Поднимите номер сборки в `app/android/app/build.gradle`:
   - `versionCode` (число, должно расти: 7, 8, 9...)
   - `versionName` (строка: "2.0.1", "2.0.2"...)
2. Запустите скрипт релиза из папки `app`:
   ```bash
   npm run release -- "Описание изменений для пользователей"
   ```
   Скрипт автоматически:
   - Соберёт веб-бандл (`npm run build`);
   - Синхронизирует ассеты в Android (`npx cap sync android`);
   - Соберёт подписанный релизный APK через Gradle;
   - Скопирует файл в `dist-apk/TickTick2-<versionName>.apk`;
   - Подготовит файлы обновления в `hosting/update/` (`version.json` и `zadachi.bin`).
3. Выложите обновление на сервер (из корня):
   ```bash
   firebase deploy --only hosting
   ```
   После этого пользователи в приложении на телефоне при нажатии «Проверить обновления» увидят кнопку скачивания новой версии.

---

### 3. Сборка Windows Desktop (.exe)
Сборка выполняется через Tauri. Из папки `app`:
```bash
# Ограничиваем число потоков компиляции Rust для стабильности памяти
$env:CARGO_BUILD_JOBS="1"
npm run desktop
```
Готовый установщик появится по пути:  
`app/src-tauri/target/release/bundle/nsis/TickTick 2.0_<версия>_x64-setup.exe`  
(также рекомендуется скопировать в папку `dist-apk/`).

## 5. Важные соглашения при доработке

1. **Размер компонентов:** UI-компоненты рекомендуется держать в пределах до 180 строк. Если компонент разрастается — выносите подкомпоненты в отдельные файлы или используйте кастомные хуки в папке `hooks/`.
2. **Локальное хранилище:** Для работы с локальными настройками и флагами используйте `StorageService` (`src/platform/storage.ts` или хук `useStorage`), чтобы типы и ключи хранились централизованно.
3. **Модальные окна и шторки:** Новые диалоговые окна регистрируются через `src/ui/modal/ModalProvider.tsx` с вызовом `openModal('имя', props)` — это избавляет код от прокидывания десятков `useState` через всё дерево.
4. **Оптимизация рендеров:** Строки задач `TaskRow` обёрнуты в `React.memo`. При добавлении пропсов убедитесь, что коллбеки стабилизированы через `useCallback`, а сложные вычисления — через `useMemo`.
5. **Тесты:** Перед каждым коммитом запускайте `npm run test` в папке `app`. Если меняется поведение задач, фильтров или повторов — дописывайте тесты в соответствующий `.test.ts` файл.
